* Technical Insights

** Conflict markers can lie about adjacent unchanged regions

The merged =flake.nix= with conflict markers showed only =nixpkgs= and =disko= inputs at the top (lines 2-4, outside any conflict region). I inferred upstream was missing the =nixos-facter-modules= input declaration and would fail to evaluate =generic-nixos-facter=. Then I ran =git show upstream/main:flake.nix= and saw =inputs.nixos-facter-modules.url= was right there at line 5.

What probably happened: git's conflict detection grouped the new input line into the upstream side of the larger output-block conflict that started just below it. The unchanged lines stayed visible at the top, the new adjacent line got absorbed into =<<<...>>>= one side. The lesson: when reasoning about what upstream has, read upstream directly (=git show <ref>:<path>=). Don't reason from the merge-state file — it's a derived artifact with its own quirks.

** Textual merge tools don't catch semantic merge conflicts

=disk-config.nix= had no textual conflict markers — local hardcoded a hetzner disk ID, upstream introduced =lib.mkDefault "/dev/sda"=, but those didn't collide line-by-line for git's purposes. The semantic conflict only surfaced when =nix flake check= caught:

#+begin_example
error: The option `disko.devices.disk.disk1.device' is defined multiple times
- In `.../disk-config.nix': "/dev/disk/by-id/scsi-0QEMU_..."
- In `.../flake.nix': "/dev/vda"
#+end_example

The fix wasn't conflict resolution; it was making the base config /composable/ via =lib.mkDefault=. Running =flake check= /before/ committing the merge was load-bearing — without it I'd have pushed broken digitalocean evaluation.

** =nix flake check= is all-or-nothing; use per-target eval for guarded targets

Upstream's =generic= and =generic-nixos-facter= contain intentional =throw= statements in placeholder files (=hardware-configuration.nix=, =facter.json=) that fire unless the operator regenerates them at deploy time. =nix flake check= evaluates everything and aborts at the first error, hiding the status of later targets.

Workaround: =nix eval ".#nixosConfigurations.<name>.config.system.build.toplevel.drvPath" --raw= per target. Returns a derivation path on success, a stack trace on failure. Loops cleanly over the targets you care about.

** =lib.mkDefault= as base-config composability primitive

Pattern worth remembering: when a NixOS module is imported by several flake outputs and some of them need to override a specific option, wrap that option's default with =lib.mkDefault=. Importers that say nothing get the default; importers that set their own value win without =mkForce=. Costs zero in the single-importer case (one definition is one definition, regardless of priority).

The deploy-time =sed= here is a hint that this option /is/ a per-host knob. Anything sed-replaced at deploy is by definition not authoritative; =mkDefault= just makes that explicit in the type system.
